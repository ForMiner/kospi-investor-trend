# 코스피 수급 추이

네이버 금융에서 코스피 투자자별 일별 순매수(개인·외국인·기관)를 수집해,
월별 / 주별 / 최근 20영업일 세 개의 라인 차트로 된 HTML 리포트를 만듭니다.

## 구성

| 파일 | 역할 |
|---|---|
| `fetch_kospi.py` | 수집 + 렌더 (리눅스·클라우드용, 표준 라이브러리만 사용) |
| `Get-KospiInvestorTrend.ps1` | 같은 일을 하는 Windows PowerShell 5.1 버전 |
| `template.html` | 차트 페이지. 두 스크립트가 공유하며 `/*__DATA__*/null` 자리에 데이터를 주입 |
| `data/kospi_investor_daily.csv` | 일별 데이터 캐시 (커밋해서 재수집량을 줄임) |
| `dist/index.html` | 생성물 — 직접 수정하지 말 것 |
| `grid_bot.py` | 그리드 매매 감시 + 알림 (아래 "그리드 매매" 참고) |
| `grid_template.html` | 그리드 분배표·거래일지 페이지 |
| `grid/config.json` | 사다리 정의 + 현재 보유 상태 |
| `data/grid_trades.csv` | 그리드 체결 기록 |
| `dist/grid.html` | 생성물 — 직접 수정하지 말 것 |

## 실행

```
python3 fetch_kospi.py --months 14
```

```
./Get-KospiInvestorTrend.ps1 -Months 14
```

`--force` / `-Force` 를 주면 캐시를 무시하고 창 전체를 다시 받습니다.
`--render-only` 는 네트워크를 전혀 쓰지 않고 커밋된 CSV만으로 리포트를 다시 만듭니다.

## 자동화 구조

수집과 발행이 두 곳으로 나뉘어 있습니다.

| 시각 (KST) | 주체 | 하는 일 |
|---|---|---|
| 평일 07:50 | GitHub Actions (`.github/workflows/fetch-kospi.yml`) | 네이버에서 새 영업일 수집 → CSV 커밋 → 리포트를 PNG로 캡처 → **텔레그램으로 차트 전송** |
| 평일 08:00 | Claude 클라우드 루틴 | 저장소 클론 → `--render-only` 렌더 → 아티팩트 갱신 |

**왜 나눴나:** Claude 클라우드 샌드박스의 이그레스 프록시는 허용 목록 방식이라
`finance.naver.com`도 `api.telegram.org`도 403으로 거부됩니다 (`WebFetch`도 동일).
GitHub 러너는 아웃바운드가 열려 있으므로 **수집과 알림 둘 다** 그쪽에 두고, 루틴은
커밋된 CSV를 읽어 렌더·발행만 합니다.

알림 문구는 `fetch_kospi.py`가 출력하는 `NOTIFY ` 줄을 그대로 씁니다. 문구나 숫자
형식을 바꾸려면 워크플로가 아니라 `notify_line()`을 고치세요.

차트 이미지는 헤드리스 크롬으로 `dist/index.html`을 그대로 캡처한 것이라, 텔레그램으로
받는 그림과 아티팩트 페이지가 어긋날 수 없습니다. 캡처 높이(`--window-size`)는 문서
전체 높이보다 커야 합니다 — 부족하면 마지막 차트가 조용히 잘립니다. 폭 1000px 기준
문서 높이는 약 1815px입니다. `template.html`에서 차트를 추가하거나 카드 높이를 바꾸면
이 값도 같이 올려야 합니다.

캡션은 숫자 한 줄뿐입니다. 아티팩트 링크는 일부러 넣지 않습니다 — 알림은 Actions가
07:50에 보내고 아티팩트는 루틴이 08:00에 갱신하므로, 링크를 넣으면 알림 직후 열었을 때
전날 차트가 보이는 어긋남이 생깁니다. 첨부 이미지와 숫자는 항상 당일 확정치입니다.

### 필요한 저장소 시크릿

Settings → Secrets and variables → Actions:

| 이름 | 값 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | @BotFather가 발급한 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 봇과의 대화 chat id |

둘 중 하나라도 없으면 알림 단계는 **실패합니다**. 일부러 그렇게 뒀습니다 — 조용히
건너뛰면 "보냈는데 안 온 것"과 "애초에 안 보낸 것"이 실행 목록에서 똑같이 초록색으로
보여서 구분할 수 없습니다. 수집과 커밋은 그 앞 단계라 알림이 실패해도 이미 끝나 있습니다.

Actions 워크플로는 `workflow_dispatch` 로 수동 실행할 수 있습니다.

## 그리드 매매

첨부 화면과 같은 **가격별 투자 분배표 + 거래일지** 페이지(`dist/grid.html`)와, 레벨이
닿을 때 **텔레그램으로 매수·매도 타이밍을 알려주는 봇**(`grid_bot.py`)입니다. 주문은
직접 내는 전제라, 봇은 자동으로 사고팔지 않고 "지금 #10을 ₩1,559,000에 14주" 처럼
할 일만 알려줍니다.

### 사다리 계산

`grid/config.json` 한 파일이 페이지와 봇의 공통 입력입니다.

| 키 | 뜻 |
|---|---|
| `code` / `name` | 종목코드(6자리) / 표시 이름. **`code`가 비어 있으면 봇은 폴링하지 않습니다.** |
| `lower` / `upper` | 사다리 하단·상단 가격 |
| `levels` | 레벨 수 (19 = 등비 간격 18칸) |
| `budget` | 사다리 전체에 넣을 원금 |
| `endMultiple` | 끝단 배수 — 맨 아래 레벨의 주문금액이 맨 위의 몇 배인가 (20 = 하단 집중) |
| `tick` | 호가 단위. `0`이면 가격대별 KRX 호가를 자동으로 씁니다 |
| `feeRate` / `taxRate` | 수수료율·매도 세율(%). 기본 0 — 수익 칸이 세전 총액이 됩니다 |
| `entryPrice` | 표에 점선으로 찍히는 진입가 |
| `holdings` | `{"12": 10}` = #12 레벨을 10주 들고 있다. 봇이 체결마다 고칩니다 |
| `sessions` | `[{"start": "...", "end": null}]` 가동 구간. 비우면 첫 체결부터 지금까지로 봅니다 |

- **가격**: `upper`에서 시작해 등비로 내려오며 호가 단위로 **내림**합니다. 올림·반올림이
  아니라 내림인 이유는 매수 지정가라서 — 이론값보다 한 틱 아래에 걸리는 편이 안전합니다.
- **금액**: 위에서 아래로 등비로 커지고, 맨 아래가 맨 위의 `endMultiple`배입니다.
  전부 더하면 정확히 `budget`이 됩니다.
- **실매수 권장 수량**은 소수 주식을 살 수 없으니 `내림(주문금액 ÷ 가격)`입니다.
- **다음 그리드 매도 수익**은 그 레벨을 실매수 수량만큼 들고 있다가 한 칸 위에서 팔았을
  때 생기는 금액입니다. 맨 위 레벨은 위에 칸이 없으므로 상단 × 간격 한 칸을 목표가로 씁니다.

같은 공식이 `grid_bot.py`의 `build_levels()`와 `grid_template.html`의 `buildLevels()`
양쪽에 있습니다. **한쪽만 고치면 알림과 표가 서로 다른 가격을 말하게 됩니다.**

### 알림 규칙

폴링마다 현재가를 받아, **직전 체결 시점의 가격에서 지금까지 지나온 레벨**만 신호로
칩니다.

- 매수: 아직 안 산 레벨을 가격이 아래로 통과 → `🟢 #10 매수 ₩1,559,000 × 14주`
- 매도: 보유 중인 레벨의 한 칸 위를 가격이 위로 통과 → `🔴 #11 매도 … (실현 +₩300,000)`

기준가를 매 폴링마다 갱신하지 않고 **마지막 체결 가격에 고정**해 두는 것이 핵심입니다.
그래야 갭이 크게 벌어졌을 때 건너뛴 레벨이 한 번에 다 나오고, 5분마다 커밋이 쌓이지도
않습니다. 첫 폴링은 기준가만 잡고 알림을 보내지 않습니다 — 이미 지나온 레벨 전부를
뒤늦게 쏟아내는 것을 막기 위해서입니다.

알림은 **상태를 쓰기 전에** 보냅니다. 텔레그램이 실패했는데 체결부터 기록해 버리면 그
신호는 영영 안 오기 때문에, 전송이 실패하면 아무것도 남기지 않고 다음 폴링에서 같은
신호를 다시 시도합니다.

**한계 하나**: 폴링 간격 사이에 잠깐 찍고 올라온 꼬리는 못 봅니다. GitHub 스케줄러는
혼잡하면 몇 분씩 밀리므로, 실제 간격은 5~15분으로 보는 편이 맞습니다. 지정가 주문을
미리 걸어두면 이 구멍은 증권사 쪽에서 메워집니다 — 알림은 "걸어둔 주문이 체결됐을
것"을 알려주는 용도로 쓰는 게 가장 안전합니다.

### 실행

```
python3 grid_bot.py                    # 시세 조회 → 신호 → 알림 → 기록 → 페이지
python3 grid_bot.py --render-only      # 네트워크 없이 페이지만 다시 그림
python3 grid_bot.py --price 1559000 --dry-run   # 그 가격이면 무슨 신호가 나오는지만 확인
```

`.github/workflows/grid-alert.yml`이 평일 09:00~15:30 KST에 5분 간격으로 돌면서
체결이 생긴 폴링에서만 `grid/config.json`과 `data/grid_trades.csv`를 커밋합니다.
`workflow_dispatch`로 가격을 넣어 손으로 시험해볼 수도 있습니다.

시크릿은 코스피 알림과 같은 `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`를 씁니다.

### 페이지에서 바꾸기

`dist/grid.html`의 설정 카드에서 하단·상단·레벨 수·원금·끝단 배수를 바꾸면 표와
차트가 바로 다시 계산됩니다. 그 값은 **브라우저에만** 저장되니, 봇까지 같은 사다리를
보게 하려면 "설정 JSON 복사"로 받아 `grid/config.json`에 넣고 커밋해야 합니다.
커밋된 설정이 바뀌면 브라우저에 남아 있던 수정본은 자동으로 버려집니다 — 봇이 보는
사다리와 화면이 조용히 어긋나는 쪽이 더 위험하기 때문입니다.

## 데이터

- 출처: `https://finance.naver.com/sise/investorDealTrendDay.naver` — `sosok=01`이 코스피, `sosok=02`가 코스닥
- 페이지 인코딩은 EUC-KR, 한 번에 10행씩만 내려오며 페이징 링크가 없습니다.
  화면에 보이는 가장 오래된 날짜의 하루 전을 `bizdate`로 넣어 거슬러 올라갑니다.
- 단위는 억원. 순매수 = 매수 − 매도.
- CSV 컬럼: `date, individual, foreign, institution, fin_invest, insurance,
  trust, bank, other_fin, pension, other_corp`

`institution`은 기관계이며, 그 뒤 여섯 컬럼(금융투자·보험·투신·은행·기타금융·연기금)의
합입니다. 리포트는 현재 개인·외국인·기관계 세 계열만 그리지만, 세부 주체도 CSV에 모두
들어 있습니다.
